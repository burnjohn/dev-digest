# DevDigest

Local-first AI PR reviewer: add repo → import PRs → run agent review → structured findings.

## Stack

- Node ≥22, pnpm ≥10, Docker (Postgres only)
- TypeScript 5.7, strict + noUncheckedIndexedAccess everywhere
- NOT a monorepo workspace — packages linked via tsconfig path aliases, each has own lockfile

## Packages

| Path | Alias | What |
|------|-------|------|
| `server/` | `@devdigest/api` | Fastify 5 API + Drizzle/Postgres (pgvector), :3001 |
| `client/` | `@devdigest/web` | Next.js 15 App Router, :3000 |
| `reviewer-core/` | `@devdigest/reviewer-core` | Pure engine: diff → prompt → LLM → grounded findings |
| `e2e/` | `@devdigest/e2e` | Deterministic browser e2e (agent-browser, no LLM) |
| `server/src/vendor/shared/` | `@devdigest/shared` | Zod contracts shared by all packages |

## Commands

```sh
./scripts/dev.sh          # boot everything (Docker + API + web)
./scripts/e2e.sh          # hermetic e2e (isolated Postgres + ports)
```

## Session Protocol

- Before non-trivial work in a package, read its `INSIGHTS.md` — what past sessions actually learned there — and name the entries that bear on the task
- Confirmed a non-obvious fact? Capture it immediately with the `engineering-insights` skill; don't batch it to the end of the session, that's where the specifics are already gone
- Before finishing a task that touched code, run `/engineering-insights` to sweep up what was missed. If nothing was worth capturing, say so explicitly

## Feature and bug-fix testing workflow

- Add or identify a focused regression test before implementing a feature or bug fix.
- Prove every new or materially changed test can fail for the intended reason: run it against the pre-fix behavior or temporarily reverse/mutate the relevant implementation, observe RED, then restore the implementation and observe GREEN.
- After focused tests pass, run the affected package's complete test and typecheck suites plus any relevant cross-package, architecture, integration, or browser checks. Do not treat a focused test alone as completion evidence.

## Conventions

- `@devdigest/shared` is the ONE source of truth for cross-package types — extend with new contract files, never edit existing ones
- `reviewer-core` never emits JS — consumed as TypeScript source via path alias
- Secrets live in `~/.devdigest/secrets.json` (mode 0600), NOT in git or DB; `process.env` is fallback
- When running from a Git worktree, reuse the primary checkout's existing `server/.env` by setting `DOTENV_CONFIG_PATH` to its absolute path before server, migration, seed, test, or review processes. Verify the file exists; do not copy secrets into the worktree or silently run with an empty environment.
- DB migrations are NOT auto-applied on boot — always `cd server && pnpm db:migrate`
- Test split: `*.it.test.ts` = DB-backed (testcontainers), everything else = hermetic

## Gotchas

- Multiple zod instances (shared vs package) — `instanceof ZodError` can fail; error handler duck-types by shape
- `reviewer-core` pins its own `zod` in tsconfig paths to avoid dual-instance issues
- pgvector extension is enabled by migration `0000` — if you get vector type errors, migrations didn't run against the right DB

## Do not touch

- `server/src/vendor/shared/` — shared contracts; coordinate changes across all consumers
- `server/src/db/migrations/` — generated by drizzle-kit, never hand-edit
- `client/src/vendor/ui/` — vendored UI primitives
