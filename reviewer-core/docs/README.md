# reviewer-core/docs

Design notes and deeper explanations for the review engine that are **too long for
[AGENTS.md](../AGENTS.md)** — pipeline rationale, grounding algorithm details,
structured-output/parse-with-repair internals, prompt-slot design for later lessons.

Rule of thumb: a *map* (where things live, a command, a one-line rule) belongs in
AGENTS.md; an *explanation* read only when a task needs it belongs here and gets linked.
