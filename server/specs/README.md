# server/specs

Feature specs and design proposals for `@devdigest/api` — what a module should do and
why, written *before* (or alongside) the code. The reviewer engine can also be fed
`specs` as a prompt slot in later lessons, so keep them in sync with intent.

One file per feature/module (e.g. `reviews.md`, `repo-intel.md`). Link the relevant
spec from a module's code or PR when it exists.
