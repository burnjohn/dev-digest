## What Doesn't Work

- `2026-08-08` — A transient EventSource error is treated as run completion: useRunEvents closes the source and sets running=false on every onerror, then RunStatus calls onDone for that transition even if the server run is still active. Native reconnect cannot simply be restored because the SSE route always replays the whole buffer while the client neither sends/uses a cursor explicitly nor deduplicates RunEvent.seq; separate terminal completion from transport failure and make resume idempotent → client/src/lib/hooks/reviews.ts:180-204; client/src/app/repos/[repoId]/pulls/[number]/_components/RunStatus/RunStatus.tsx:20-26; server/src/modules/reviews/routes.ts:62-84

## Codebase Patterns

- `2026-08-01` — An effect that opens an `EventSource` must depend on a PRIMITIVE key, never on the array or object of ids: `useRunEvents` keys on `runIds.join(",")` because a fresh array identity every render tears down and reopens every stream, so each render refetches the whole replay buffer and hammers the API (symptom: a flood of `/runs/:id/events` requests and events that keep resetting). The `react-hooks/exhaustive-deps` disable directly above the dep array is load-bearing — putting `runIds` back in the deps reintroduces the loop → `client/src/lib/hooks/reviews.ts:171` (key) and the eslint-disable at :212
- `2026-08-01` — SSE frames are parsed and accumulated in the client (`useRunEvents`), deliberately not behind a server-side aggregation endpoint: the UI needs incremental per-event updates regardless, and the RunBus stream is replay-first — it keeps its buffer after a run completes so a late subscriber replays full history before going live — so a server-side snapshot/aggregate endpoint would add a second code path for data the client already has → `client/src/lib/hooks/reviews.ts:168`, late-subscriber buffer retention at `server/src/platform/sse.ts:43`
- `2026-08-03` — vendor/ui has no Tooltip/Popover primitive (and is read-only) — a hover popover is built locally with React state, and the panel must be a DOM CHILD of the position:relative anchor: mouseleave then doesn't fire while the pointer travels into the panel, so no close-delay timers; make the visual gap with paddingTop on the panel, not a top offset, or the dead strip closes it mid-way → RunSeverityBadges/RunSeverityBadges.tsx, RunFindingsPopover.tsx (PR #8)
- `2026-08-05` — src/vendor/shared here is a real hand-maintained copy of the server's canonical contracts, NOT a symlink as this package's CLAUDE.md states — adding or changing a shared contract means editing the server copy too, and the two have already drifted → see the root INSIGHTS.md entry dated 2026-08-05 for the exact drifted files and the `diff -rq` that shows them
- `2026-08-06` — vendor Dropdown (kit/Dropdown.tsx) keys items by array index, not a stable id — when a component builds `items` from data that loads asynchronously after first render (e.g. a token list fetched on mount), opening the dropdown before that fetch resolves puts a placeholder item (e.g. "+ New token") at index 0; when the fetch resolves and shifts indices, React reuses that same key-0 DOM node for whatever item is now at index 0, mutating its text/icon in place instead of creating a new node. A test that finds a placeholder item right after opening the dropdown can capture that soon-to-be-mutated node and click on content that has since become a different item by the time the click fires — reproduced by logging document.body.innerHTML before/after. Fix in tests: wait for the async data to settle (e.g. wait for a known loaded-item label to render) before querying for order-dependent placeholder items, and re-query fresh right before clicking rather than reusing an earlier handle → client/src/components/github-token-picker/GitHubTokenPicker.test.tsx (the "reveals the inline create form" test and its comment)
- `2026-08-06` — No page.tsx under client/src/app anywhere uses Next 15's async `params: Promise<{...}>` server-component pattern — every dynamic-route page (pulls/page.tsx, pulls/[number]/page.tsx, and repos/[repoId]/settings/page.tsx) is "use client" and reads the route param via useParams<{...}>() from next/navigation instead. A task brief that says to copy how an existing page "awaits params" may be describing a pattern that isn't actually in that file — read the file before assuming Promise-params → client/src/app/repos/[repoId]/pulls/page.tsx, client/src/app/repos/[repoId]/settings/page.tsx (PR feat/per-repo-github-tokens Task 11)
- `2026-08-06` — The CSS custom property for the amber/warning color is --warn (and --warn-bg), not --warning — a var(--warning) reference silently renders as an invalid/no-op inline style rather than erroring, since inline style values aren't typechecked → client/src/vendor/ui/styles.css :root blocks (both themes) (PR feat/per-repo-github-tokens Task 11)
- `2026-08-06` — client/src/app/onboarding/_components/AddRepoView/AddRepoView.tsx does not use next-intl/useTranslations at all — every string is hardcoded inline JSX text; messages/en/onboarding.json is for the unrelated onboarding-tour generator feature, not this add-repo screen. Follow the file's own hardcoded-string convention rather than introducing i18n keys for it → client/src/app/onboarding/_components/AddRepoView/AddRepoView.tsx (PR feat/per-repo-github-tokens Task 11)
- `2026-08-20` — The SSE wire protocol has NO terminal 'done' event — the server simply ends the stream on RunBus.complete(), and a browser EventSource treats a server-side end identically to a network blip (auto-reconnect); client-side run completion therefore comes from the active-runs poll (didRunsSettle), and any reconnect-tolerant consumer must dedupe replayed events by runId:seq → client/src/lib/hooks/reviews.ts, client/src/app/repos/[repoId]/pulls/[number]/helpers.ts, 2026-08-20
